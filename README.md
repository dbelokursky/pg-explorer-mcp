# pg-mcp

MCP-сервер для PostgreSQL с доступом только на чтение: для GigaCode CLI и других агентов
семейства Qwen Code. Написан на Python 3.9+ без внешних зависимостей: драйвер pg8000 лежит
в репозитории, ставить ничего не нужно.

## Что умеет

| Инструмент | Что делает |
|---|---|
| `status` | к какой базе подключён, под какой ролью, версия PostgreSQL и действующие лимиты |
| `list_tables` | таблицы, представления и внешние таблицы, которые роль может читать, с оценкой числа строк и комментариями; не больше 200 за раз |
| `describe_table` | колонки с типами, `NOT NULL`, значениями по умолчанию и комментариями, ключи, таблицы, которые ссылаются на эту, и индексы |

Сессия открывается в режиме только чтения с таймаутом запроса, а каждый запрос уходит одной
командой через extended protocol. Это страховка, а не граница: настоящая граница — права роли.
Заведите для агента отдельную роль с `SELECT` только на нужные таблицы; черновик роли и
политика разрешённого SQL — в [docs/adr/0002-read-only-sql-policy.md](docs/adr/0002-read-only-sql-policy.md).

Каждый ответ инструмента укладывается в бюджет — по умолчанию 8000 символов, меняется переменной
`PG_MCP_MAX_RESPONSE_CHARS`. Локальные модели работают с небольшим контекстом, а слишком длинный
ответ может оборвать сессию агента.

## Установка

Нужен Python 3.9 или новее. На macOS он приходит вместе с Command Line Tools (их ставит git),
на Linux есть почти везде. На Windows — установщик с python.org (`py -3`) или embeddable-архив,
который распаковывается без прав администратора.

1. Склонируйте репозиторий.
2. Зарегистрируйте сервер в GigaCode. Скрипт сохранит копию настроек, пропишет сервер
   и проверит, что он запускается и видит базу:

   ```bash
   python3 install.py
   ```

   На Windows — `py -3 install.py`, для Qwen Code — `python3 install.py --client qwen`.
3. Подключите расширение: оно даёт агенту короткий контекст и команду `/pg:setup`
   для самопроверки и починки:

   ```bash
   gigacode extensions link /путь/к/pg-mcp
   ```

4. Перезапустите GigaCode.

### Подключение к базе

Сервер читает те же переменные, что psql: `PGHOST`, `PGPORT`, `PGDATABASE`, `PGUSER`,
`PGSSLMODE`, `PGSSLROOTCERT`. Если они заданы в терминале при запуске `install.py`, скрипт
перенесёт их в блок `env` сервера в `~/.gigacode/settings.json`; дальше их можно править там.

Пароль храните только в `~/.pgpass` (на Windows — `%APPDATA%\postgresql\pgpass.conf`): одна
строка `host:port:database:user:password`, права 600. Ни в настройки агента, ни в чат его
не кладите.

Проверить подключение: `python3 install.py --check` — или попросите агента проверить
подключение к базе, он вызовет `status`.

## Разработка

Тесты используют только стандартную библиотеку:

```bash
python3 -I -m unittest discover -s tests
```

Интеграционные тесты ходят в настоящий PostgreSQL и создают и удаляют схемы `mcp_it` и `mcp_it_archive`:

```bash
PG_MCP_IT=1 PGHOST=localhost PGDATABASE=pg_mcp_test python3 -I -m unittest discover -s tests
```

Почему всё устроено именно так — в [docs/adr/0001-python-stdlib-only.md](docs/adr/0001-python-stdlib-only.md).
Что лежит в `server/vendor/` и как это обновлять — в [server/vendor/README.md](server/vendor/README.md).
