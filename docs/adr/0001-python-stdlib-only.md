# ADR 0001. Python без внешних зависимостей

Статус: принято, 2026-10-22.

## Контекст

- Клиент — GigaCode CLI, форк семейства Qwen Code / Gemini CLI. Публичной документации
  у него нет: известное собрано из расширений сообщества и разбора сборки 0.13.1.
- Сервер работает локально у каждого пользователя и общается с агентом через stdio.
  Агент работает на моделях Qwen или DeepSeek, развёрнутых в организации.
- Раздаём только исходники из репозитория, собранные артефакты не распространяем.
  В корпоративном режиме GigaCode ставит расширения только из локальной папки.
- Пользователи — разные группы, и гарантированного рантайма у них нет: JDK есть не у всех,
  Node тоже может не оказаться, сеть корпоративная (SSL inspection, зеркала).
- Python 3.9+ есть почти везде: на Linux — системный, на macOS — вместе с Command Line Tools
  (3.9.6), на Windows — у части пользователей.

## Решение

- Python 3.9+, только стандартная библиотека.
- Протокол MCP (JSON-RPC через stdio) реализуем сами в объёме сервера, который предоставляет
  только инструменты: `initialize`, `ping`, `tools/list`, `tools/call`; ревизии с 2024-11-05
  по 2025-11-25.
- Драйвер PostgreSQL — pg8000 (чистый Python, BSD-3-Clause) с зависимостями scramp, asn1crypto,
  python-dateutil и six. Их исходники лежат в `src/pg_explorer_mcp/_vendor/` вместе с лицензиями.
- Регистрация — `install.py`: прописывает сервер в `~/.gigacode/settings.json` с абсолютным
  путём к интерпретатору, на котором запущен, и проверяет запуск. Расширение
  (`gigacode-extension.json`) даёт агенту короткий контекст и команду `/pg:setup` для починки.

## Рассмотренные варианты

| Вариант | Почему нет |
|---|---|
| Java + Spring AI или MCP Java SDK | JDK есть не у всех; сборка из исходников требует Maven и настроенного зеркала |
| TypeScript + официальный SDK | Node может не быть в PATH: GigaCode и standalone-сборка Qwen Code возят свой Node и наружу его не выставляют |
| Go, один бинарник | раздаём только исходники, а Go-тулчейна у пользователей нет |
| Официальный Python SDK (`mcp`) | требует Python 3.10+, pip и нативные пакеты (pydantic-core, cryptography, pywin32) |
| Удалённый сервер | требование — локальный сервер у каждого пользователя |

## Последствия

- Код протокола наш: соответствие спецификации держим тестами, за новыми ревизиями следим сами.
- Ревизия 2026-07-28 убрала `initialize`: версия протокола едет в `_meta` каждого запроса, а
  `server/discover` сообщает, какие ревизии понимает сервер. С версии 0.2.0 сервер поддерживает обе
  эпохи: запрос с версией в `_meta` обслуживается по 2026-07-28, `initialize` включает старые правила.
- stdin читается байтами, ответы — JSON только из ASCII, поэтому кодовая страница консоли
  Windows (cp866/cp1251) протокол не ломает.
- `Database.query` выполняет ровно одну команду через extended protocol, и строку
  `SELECT 1; COMMIT; DROP ...` PostgreSQL отвергнет. Это закрывает класс дыр, найденный
  в архивном эталонном сервере `server-postgres`.
- Зависимости в `src/pg_explorer_mcp/_vendor/` обновляем вручную, по инструкции в `src/pg_explorer_mcp/_vendor/README.md`.
