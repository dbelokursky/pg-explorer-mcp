# ADR 0007. Имя pg-explorer-mcp

Статус: принято 2026-10-26.

## Контекст

Под именем `pg-mcp` на PyPI уже есть другой проект с тем же назначением: andre-c-andersen/pg-mcp, форк
crystaldba/postgres-mcp. У него тот же пакет `pg_mcp` и та же команда `pg-mcp`. pip отличает проекты
только по имени дистрибутива. Поэтому `pip install -U pg-mcp` заменил бы копию, поставленную из git,
чужим пакетом, а две копии в одном окружении затирали бы файлы друг друга. Человек или агент, который
угадает `uvx pg-mcp` по имени, поставит другой сервер. Каталоги MCP и оценщики вроде M8ven тоже путают
два проекта с одним именем.

Сервер уже установлен у пользователей: клоны и распакованные архивы, записи в настройках агентов с
переменными `PG_MCP_*`, реестры стендов в `~/.pg-mcp/`, выгрузки в DBeaver, VS Code и `pg_service.conf`,
подключённое расширение Qwen Code. Новое имя не должно ломать ничего из этого.

## Решение

Продукт называется pg-explorer-mcp. Сохранённое у пользователей либо читается в обоих вариантах, либо
остаётся как было.

| Что | Было | Стало | Совместимость |
|---|---|---|---|
| Репозиторий | `dbelokursky/pg-mcp` | `dbelokursky/pg-explorer-mcp` | GitHub перенаправляет старые ссылки и git-URL |
| Дистрибутив, пакет, команда | `pg-mcp`, `pg_mcp`, `pg-mcp` | `pg-explorer-mcp`, `pg_explorer_mcp`, `pg-explorer-mcp` | клиенты запускают `run.py`, он меняется вместе с пакетом |
| Переменные | `PG_MCP_*` | `PG_EXPLORER_MCP_*` | `environment.py` на входе сервера, `install.py` и скриптов подставляет старое имя, если нового нет; новое важнее; `install.py` пишет только новые |
| Ответы, журнал, `application_name` | `pg-mcp` | `pg-explorer-mcp` | — |
| Папка реестра стендов | `~/.pg-mcp/`, `%APPDATA%\pg-mcp\` | `~/.pg-explorer-mcp/`, `%APPDATA%\pg-explorer-mcp\` | пока в новой папке нет `stands.conf`, сервер, импорт и выгрузки берут старую |
| Строка выгрузки в `pg_service.conf` | `# pg-mcp export` | `# pg-explorer-mcp export` | старая тоже узнаётся; выгрузка переписывает такие разделы под новой |
| Архив выпуска | `pg-mcp-X.Y.Z.zip`, папка `pg-mcp/` | `pg-explorer-mcp-X.Y.Z.zip`, папка `pg-explorer-mcp/` | при переходе на 0.8.0 один раз запустить `install.py` из новой папки |
| Расширение | `pg-mcp`, `pg-mcp-context.md` | `pg-explorer-mcp`, `pg-explorer-mcp-context.md` | см. ниже |

## Что осталось как было

- **Файл `data-sources-pg-mcp.json` и id подключений** в DBeaver (`postgres-jdbc-pg-mcp-…`) и VS Code
  (`pg-mcp-…`). К ним эти инструменты привязывают настройки пользователя. С новыми id выгрузка удалила бы
  прежние подключения и создала новые, и эти настройки пропали бы.
- **Записи MCP** `pg`, `pg-<name>`, `pg-stands` и команды `/pg:*`. Имени продукта в них нет, а на них
  ссылаются правила разрешений в клиентах.
- **История**: прошлые разделы CHANGELOG и рассуждения ADR 0001–0006. В ADR поправлены только ссылки на
  текущее устройство: пути к файлам, имена переменных, `application_name`.

## Расширение

Qwen Code при подключении (`extensions link`) заводит папку
`~/.qwen/extensions/<имя из манифеста>/` с путём к папке расширения. При каждом запуске клиент заново
читает манифест по этому пути, а имя берёт из манифеста. Поэтому после `git pull` прежняя запись `pg-mcp/`
загружается как `pg-explorer-mcp`, без ошибки и без дубля, и новый файл контекста тоже подхватывается.

Ломается удаление. `extensions uninstall` ищет папку по текущему имени, не находит её и оставляет старую
запись. Пока она есть, `extensions link` отвечает, что расширение уже установлено. Помогает только удалить
`~/.qwen/extensions/pg-mcp`. `install.py` называет эту папку, если она
есть, но сам её не трогает: это хранилище клиента, и его формат зависит от версии клиента. Включено ли
расширение, клиент хранит по имени. Кто выключал `pg-mcp`, после перехода увидит его снова включённым.

## Рассмотренные варианты

- **Переименовать только дистрибутив.** Убирает путаницу у pip, но пакет и команда по-прежнему
  совпадают с чужими, а в каталогах и поиске остаются два pg-mcp.
- **Попросить имя на PyPI по PEP 541.** Так передают только заброшенный проект, владелец которого
  недоступен. Здесь это не так.
- **Оставить старые имена у переменных, папки реестра и строки выгрузки.** Ничего не нужно читать в двух
  вариантах, но старое имя навсегда осталось бы в документации и настройках.
- **Оставить имя расширения `pg-mcp`.** Удаление не ломается, но расширение называлось бы не так, как
  продукт.

## Последствия

- Старые имена переменных, папка `~/.pg-mcp/` и строка `# pg-mcp export` читаются как минимум до 1.0.
  Убирать их можно только отдельным решением, с записью в CHANGELOG за выпуск до этого.
- `client_smoke.py` и `agent_eval.py` берут имя расширения и файл контекста из манифеста. Следующее
  переименование не потребует править проверки.
- Тексты для модели (`i18n.py`, `commands/pg/*.md`, файл контекста) изменились, поэтому выпуск 0.8.0
  проверяется прогоном `scripts/agent_eval.py`.
